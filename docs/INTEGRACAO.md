# Incorporação de exemplos

Preserve os três HTML e seus caminhos atuais. Eles já pertencem ao histórico público; reorganizar a árvore inteira não acrescenta valor.

Pacotes adicionais podem ocupar `examples/premium/`, `examples/video/` e `examples/automation/`. Isso é contrato de estrutura, não afirmação de entrega. Não se criam pastas vazias, novas implementações ou assets genéricos para preencher a vitrine.

Cada pacote precisa de README com comando de execução e encerramento, dependências declaradas, fontes selecionadas, fixtures fictícias, proveniência/hashes/atribuições, capturas da versão revisada e prova dos comandos/interações prometidos.

O caso premium deve preservar a profundidade de páginas, idiomas e jornadas da variação escolhida. Uma landing page não o substitui. A variação pública pode usar marca e imagens fictícias, sem material institucional não liberado. Recursos simulados continuam identificados.

Vídeo e automação são produzidos em seus próprios projetos. A integração recebe cópias liberadas e selecionadas; não incorpora pastas de trabalho, configurações pessoais, bancos vivos, históricos de contas ou logs.

## Código e hospedagem

A revisão prepara uma branch de código e não configura hospedagem. A base pública já tem GitHub Pages ligado a `main`; um push nessa branch pode atualizar o site. Conferir destino/autorização antes de qualquer envio. Não alterar Pages, domínio ou perfil de plataforma para integrar código.
